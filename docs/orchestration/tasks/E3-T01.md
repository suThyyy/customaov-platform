## Yêu cầu
- `GET /api/auth/csrf`, `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me` đúng request/response theo contracts.
- Phiên:
  - token 32 byte, DB lưu SHA-256;
  - cookie `sid` `HttpOnly; SameSite=Lax; Path=/` (+`Secure` khi production);
  - hạn 30 ngày, trượt khi còn dưới 15 ngày;
  - logout xoá phiên và cookie.
- CSRF ký gắn phiên (API.md 9.5): `nonce.HMAC_SHA256(CSRF_SECRET, nonce + ":" + (sessionIdHash ?? "anon"))`.
  - Mọi POST/PUT/PATCH/DELETE dưới `/api` phải có header `x-csrf-token` bằng cookie và chữ ký hợp lệ với phiên hiện tại; sai → 403 `CSRF`.
  - Login, logout, register cấp cookie `csrf` mới.
  - `GET /me` đặt cookie nếu chưa có.
  - So sánh bằng `timingSafeEqual`.
- Rate limit:
  - login 5/phút theo IP **và** 10/15 phút theo cặp IP+username;
  - register 5/giờ theo IP.
  - Vượt → 429 `RATE_LIMITED`.
- Lỗi đăng nhập trả thông báo chung, không nói sai field nào. So mật khẩu luôn chạy scrypt, kể cả khi user không tồn tại (chống đoán user qua thời gian phản hồi).
- Không log body `/api/auth/*`. Redact giữ nguyên, thêm `*.csrf`, `*.csrfToken`.
- `uid` 6 chữ số ngẫu nhiên, không trùng. Username viết thường.

## Test (Vitest + `app.inject` + PGlite memory)
- register (201, set cookie `sid` HttpOnly+SameSite=Lax), trùng username → 409, body sai → 400;
- login đúng/sai (401 thông báo chung);
- `me` khi khách và khi đã đăng nhập;
- logout;
- CSRF: thiếu header → 403, header ≠ cookie → 403, token của phiên khác (anon dùng sau login) → 403, đúng → OK;
- rate limit login: lần thứ 6 trong 1 phút → 429;
- log không chứa mật khẩu, cookie, csrf (bắt log bằng `loggerStream`);
- hạn phiên và gia hạn trượt (giả lập thời gian).
